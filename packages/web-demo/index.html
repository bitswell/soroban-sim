WebAssembly Component Model why this simulator runs in your browser at all
01

Core wasm speaks only numbers

A raw wasm module's imports and exports can only pass four scalar types — i32, i64, f32, f64. No strings, no records, no lists. Anything richer has to be hand-marshalled through linear memory by both sides.

02

The Component Model adds types

A component wraps core wasm in a typed interface described in WIT (Wasm Interface Types). The Canonical ABI defines exactly how strings, records, lists and results lower to those scalars — so components compose across languages with no glue by hand.

03

jco transpiles it to JS

jco transpile turns a .wasm component into plain JavaScript plus the inner core module(s). The generated glue implements the Canonical ABI in JS, so the component runs unmodified in the browser or Node — which is exactly what loads in this page's Worker.

04

How soroban-sim uses it

The simulator is the component — world simulator, exporting simulate and needs-state. The Soroban contracts stay plain core wasm executed by the host inside it. jco lets that whole engine run here, off the main thread.
